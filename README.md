# BodyCodi → Google Calendar Sync

> 이 브랜치는 **보강 기능 검토용 초안**입니다. 운영 릴리스가 아니며 아직 설치·배포·예약 실행하지 않았습니다.
> [구현 범위, 검증 결과, 실제 원본 연결 및 배포 조건](docs/enrichment-rollout.md)을 먼저 확인하세요.
> 미확인 횟수는 보존합니다. 기존 PC는 기본 `legacy` 모드로 계속 동작하고, 공유 조정은 명시적으로 전환한 PC에만 적용됩니다. 클라우드 쓰기는 별도 활성화 전까지 차단됩니다.
> 공유 잠금은 **모의 API에서 검증한 구현**이며 실제 캘린더에 구성되지 않았습니다. 아래 설치·주기 안내는 기존 v1.18.0 운영 안내이고, 이 초안의 배포 안내가 아닙니다.
> [실제 UI 근거와 클라우드 연결을 완성하는 다음 단계](docs/source-runtime-path.md)도 확인하세요.

바디코디 스케줄표의 회원 정보를 Google Calendar 이벤트 제목에 자동 반영하는 Chrome 확장 프로그램입니다.

- 제목 포맷: `회원번호 성함 연락처 프로그램이름`
- 설명(description) 자동 라인 (v1.13.0+, 값이 있는 항목만):
  ```
  프로그램명 : PT 20회
  유효기간 : 2026-01-01 ~ 2026-12-31
  총횟수 : 20회
  잔여횟수 : 7회
  ```
- 동기화 범위: **4주 (이번 주 일요일 ~ 3주 뒤 토요일)** (v1.15.0+, `background.js`의 `SYNC_WEEKS`로 조절)
- 자동 동기화: **평일 09:00 ~ 21:00, 팝업에서 고른 주기(15분 ~ 24시간, 기본 1시간)** (토·일은 자동 스킵)
- 즉시 동기화 / 미리보기 지원

## 👥 직원용 설치 (각 PC에서 1회)

### 0단계 — ⭐ 영구 설치 (Chrome 재시작 후에도 사라지지 않음)

ZIP을 임시 폴더에 풀고 그 안의 **`INSTALL.bat`을 더블클릭**하세요.

스크립트가 자동으로:
1. 확장 파일을 `%LOCALAPPDATA%\bodycodi-sync` 로 복사
2. **Chrome 바로가기에 `--load-extension` 플래그 자동 주입** (데스크탑 / 시작메뉴 / 작업표시줄)
3. 결과: **어떤 방식으로 Chrome을 켜도 확장이 매번 자동 로드됨** → 컴퓨터를 껐다 켜도 사라지지 않음

> 🛑 **D:\ 드라이브, 바탕화면, 다운로드 폴더에 두면 안 됩니다.**
> Chrome 부팅 시 해당 경로가 늦게 마운트되거나 권한 문제로 인식 실패 → 확장이 사라지는 원인입니다.
> 또한 폴더 경로에 **공백이나 한글이 있으면 일부 Chrome 버전에서 불안정**합니다.

> 🔧 **작업표시줄 Chrome 아이콘은 추가 작업 필요**:
> 현재 핀된 아이콘을 우클릭해서 "작업표시줄에서 제거" → 데스크탑이나 시작메뉴의 (이미 수정된) Chrome 아이콘을 다시 작업표시줄에 핀.

> 🔄 **되돌리기**: `UNINSTALL.bat` 실행 → 바로가기 플래그 제거 + 폴더 삭제.

### 1단계 — 폴더 받기
INSTALL.bat 을 사용하지 않을 경우, 다음과 같은 안정 경로에 직접 복사하세요:
- ✅ 권장: `C:\Users\<사용자명>\AppData\Local\bodycodi-sync`
- ✅ 가능: `C:\bodycodi-sync`
- ❌ 비권장: `D:\...`, `바탕화면\...`, `다운로드\...`

### 2단계 — Chrome에 로드
1. Chrome 주소창에 `chrome://extensions` 입력
2. 우측 상단 **"개발자 모드"** 토글 ON
3. 좌측 상단 **"압축해제된 확장 프로그램을 로드합니다"** 클릭
4. `bodycodi-sync` 폴더 선택

### 3단계 — Extension ID 확인 (선택)
설치 후 표시되는 ID가 `clgekekmmlpiggplilhgagfkepepjelk` 인지 확인합니다. 다르다면 폴더 안의 `manifest.json`이 수정/손상된 것이니 관리자에게 문의하세요.

### 4단계 — 첫 실행 (3단계 온보딩)
브라우저 우측 상단의 확장 아이콘을 클릭하면 안내가 보입니다:
1. **바디코디 스케줄 페이지 열기** (`https://crm.bodycodi.com/manager/schedule/promise`)
2. 팝업의 **"강사 목록 불러오기"** 클릭 → 본인 Google 계정 로그인
3. 강사별로 본인 캘린더 선택 → **"매핑 저장"**

저장이 완료되면 매일 자동 동기화됩니다.

## 🔧 관리자용 1회 셋업 (Google Cloud Console)

이 작업은 **단 한 번**만 하면 되고, 이후 모든 직원 PC에서 자동으로 작동합니다.

### A. Google Cloud Project 준비
1. https://console.cloud.google.com/ 접속
2. 우측 상단 프로젝트 선택 → **새 프로젝트** (예: `bodycodi-sync`)

### B. Calendar API 활성화
1. 좌측 메뉴 → **API 및 서비스** → **라이브러리**
2. `Google Calendar API` 검색 → **사용 설정**

### C. OAuth 동의 화면 (External, 내부 사용 OK)
1. **API 및 서비스** → **OAuth 동의 화면**
2. **External** 선택 → 만들기
3. 앱 이름, 사용자 지원 이메일, 개발자 이메일 입력
4. **테스트 사용자**에 직원들의 Google 이메일 추가 (또는 게시 상태로 변경)

### D. OAuth 클라이언트 ID 생성 (핵심)
1. **API 및 서비스** → **사용자 인증 정보** → **사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
2. 애플리케이션 유형: **Chrome 확장 프로그램**
3. **애플리케이션 ID** 칸에 다음 ID 정확히 입력:
   ```
   clgekekmmlpiggplilhgagfkepepjelk
   ```
4. **만들기** → 발급된 client_id 복사 (예: `1234567...apps.googleusercontent.com`)

### E. manifest.json 업데이트
`manifest.json`을 열고 `oauth2.client_id`를 위에서 받은 값으로 교체:

```json
"oauth2": {
  "client_id": "여기에-새로-받은-client-id.apps.googleusercontent.com",
  "scopes": [
    "https://www.googleapis.com/auth/calendar"
  ]
}
```

> 만약 기존 client_id를 그대로 쓰려면, 기존 OAuth 클라이언트의 "애플리케이션 ID"를 위 Extension ID로 변경하면 됩니다. 그러나 보통은 새로 만드는 게 깔끔합니다.

### F. 직원에게 폴더 배포
설정 완료 후 폴더 전체를 ZIP으로 묶어서 직원에게 전달하면 됩니다.

## ⏰ 자동 동기화 조건

자동 동기화(평일 09~21시, 팝업에서 고른 주기)가 실행되려면 그 시각에 아래 두 가지가 필요합니다.

1. **크롬이 켜져 있어야 함** — 꺼져 있던 동안의 회차는 크롬을 켜면 한 번 실행되고, 이후 다음 시각에 이어집니다.
2. **크롬에서 바디코디에 로그인돼 있어야 함** — ⭐ v1.16.0부터는 스케줄 탭을 열어 둘 필요가 없습니다. 동기화 때마다 확장이 바디코디 스케줄 화면을 **백그라운드 새 탭**으로 열어 최신 데이터를 읽고 바로 닫습니다(약 15초, 탭 줄에 잠깐 보였다 사라짐).

로그인이 풀려 새 탭으로 읽지 못하면 자동 동기화는 그 회차를 **건너뜁니다**. 오래된 화면 데이터로 다른 PC가 맞춰 둔 일정을 되돌리지 않기 위해서입니다. 수동 "지금 동기화"는 이때 열려 있는 스케줄 탭을 다시 읽어서 진행합니다.

### 취소·사라진 예약·중복 처리 (v1.18.0부터 삭제)

바디코디가 기준입니다. 바디코디에서 취소·삭제된 예약과 같은 예약의 중복 일정은 캘린더에서 **삭제**합니다(구글 캘린더 휴지통에서 30일간 복구 가능).

| 상황 | 캘린더에서 |
|---|---|
| 바디코디에서 예약이 "취소" 상태가 됨 | 일정 삭제 |
| 바디코디에서 예약이 아예 사라짐 (삭제, 4주 밖으로 이동) | 일정 삭제 |
| ⭐ 같은 예약의 일정이 2개 이상 (확장 + 바디코디 자체 연동 등) (v1.18.0) | 1개만 남기고 삭제 |
| 바디코디에서 지웠는데 데이터엔 남고 **화면에서만 사라짐** (v1.17.0) | 일정 삭제 — 로그 사유 "바디코디 화면에서 사라짐(삭제·취소)" |
| 예전 버전이 `[취소]` 표시해 둔 일정 | 예약이 살아 있으면 표시 해제·색 복구, 여전히 취소면 삭제 |
| 담당 강사가 바뀜 | 일정을 새 강사의 캘린더로 **옮김** |
| 확장이 만든 적 없는 고객 일정인데 바디코디에 예약이 없음 (직접 입력) | **지우지 않고** 📍로 보고만 — 사유 함께 표시 |
| 개인 일정 (가족일정·회의 등 회원 정보 없는 일정) | 절대 건드리지 않음 (예약과 같은 시각이어도 이름을 바꾸지 않음) |

안전장치 (오판으로 멀쩡한 일정을 지우지 않도록):

- 모든 삭제는 동기화 전용 새 탭으로 **최신 데이터**를 읽었을 때만 합니다. 열린 탭으로 대신 읽은 경우에는 삭제하지 않고 `⏸️삭제보류`로 알립니다.

- "사라짐"은 최신 데이터로 읽은 주만 판정합니다. 화면 로딩이 시간초과된 주·읽지 못한 주의 일정만 보류하고(📍에 사유 표시), 나머지 주는 그대로 반영합니다 (v1.18.1).
- **캘린더(강사)마다 따로** 판정합니다. 그 강사의 예약이 이번 데이터에 하나도 없으면(바디코디 화면에 강사 필터가 걸린 경우 등) 그 캘린더는 보류합니다. 다른 강사 캘린더는 막히지 않습니다.
- 한 캘린더에서 한꺼번에 너무 많이 사라지면(그 캘린더 고객 일정의 50%, 최소 5건 초과) 그 캘린더만 보류합니다.
- 예약이 0건으로 읽힌 주의 일정은 보류합니다(연휴가 아니라면 로딩 실패일 수 있음).
- "화면에서만 사라짐"은 그 강사의 다른 예약이 같은 화면에 그려져 있고, 숨겨진 것이 1건이거나 1/3 이하이며, 표시 시간대 안의 예약이고, 0.4초 뒤 다시 봐도 안 그려져 있을 때만 판정합니다.
- 보류된 건수는 결과 줄의 `⏸️삭제보류`와 로그의 `⏸️` 줄로 알려 줍니다. 바디코디가 취소를 어떤 값으로 표시하는지는 `📊 예약 상태값` 줄로 확인할 수 있습니다.

## 🚀 자동 배포 (v1.13.2+) — GitHub main → 모든 직원 PC

`INSTALL.bat`을 한 번 실행한 PC는 이후 **GitHub `main` 브랜치에 올라간 새 버전을 10분마다 스스로 내려받고**, 확장이 1분 안에 다시 불러옵니다. 관리자는 main에 머지만 하면 됩니다.

**동작 원리**
1. `INSTALL.bat` → Windows 작업 스케줄러에 `BodyCodiSync-AutoUpdate` 작업 등록 (10분 간격, 창 없이 실행)
2. `AUTO-UPDATE.ps1`이 GitHub의 `manifest.json` 버전을 조회 → PC 버전보다 **높을 때만** 저장소 ZIP을 받아 확장 폴더에 덮어씀 (`manifest.json`은 마지막에 복사)
3. 확장의 자동 리로드(아래)가 버전 변경을 감지해 재적용
4. 결과는 `%LOCALAPPDATA%\bodycodi-sync\update.log`에 기록 (최신 상태면 기록 없음)

**저장소가 비공개(private)인 경우** 둘 중 하나가 필요합니다:
- (권장) GitHub 저장소를 **Public**으로 전환 — 저장소에는 비밀키(.pem)가 없고 OAuth client_id와 공개키만 있어 공개해도 무방합니다. 토큰 관리가 필요 없습니다.
- 또는 GitHub에서 이 저장소 **Contents: Read-only** 권한의 fine-grained 토큰을 만들어, 각 PC의 `%LOCALAPPDATA%\bodycodi-sync\github-token.txt`에 한 줄로 저장

**처음 한 번 (PC마다)**: 최신 ZIP을 받아 `INSTALL.bat` 실행. 이미 설치된 PC도 새 `INSTALL.bat`을 한 번 더 실행해야 작업 스케줄러가 등록됩니다. 저장소가 Public이면 PowerShell 창에 아래 한 줄을 붙여넣어도 됩니다:

```powershell
$t="$env:TEMP\bcsync"; Remove-Item $t -Recurse -Force -ErrorAction SilentlyContinue; New-Item -ItemType Directory $t | Out-Null; Invoke-WebRequest https://github.com/dckook1982-hub/bodycodi/archive/refs/heads/main.zip -OutFile "$t\s.zip"; Expand-Archive "$t\s.zip" $t; & (Get-ChildItem $t -Recurse -Filter SETUP-PERMANENT.ps1 | Select-Object -First 1).FullName
```

**되돌리기**: `UNINSTALL.bat`이 작업 스케줄러 등록도 함께 해제합니다.

## 🔄 자동 업데이트 (v1.12.0+)

확장 폴더의 파일이 갱신되면 **1분 안에 자동으로 감지해서 스스로 다시 불러옵니다.** chrome://extensions에서 새로고침 버튼을 누를 필요가 없습니다.

**동작 원리**: 확장이 1분마다 폴더에 저장된 `manifest.json`의 버전과, 현재 크롬에 실행 중인 버전을 비교합니다. 다르면 새 파일이 들어온 것이므로 `chrome.runtime.reload()`로 재시작합니다.

- ✅ 여러 파일을 수정하는 도중에는 리로드되지 않습니다 (버전은 릴리스 마지막에 올라가므로 안전)
- ✅ 동기화가 진행 중이면 끝날 때까지 리로드를 미룹니다
- ✅ 리로드 후에도 버전이 그대로면(=실패) 무한 반복하지 않고 로그로 알립니다
- ⚠️ **최초 1회는 수동 새로고침이 필요합니다** (자동 업데이트 기능 자체가 들어있는 버전을 적용해야 하므로)

성공 시 로그에 `✅ 자동 업데이트 완료 — v1.12.0 적용됨` 이 남습니다.

### 다른 직원 PC까지 자동 배포하려면

위 기능은 "폴더의 파일이 바뀌면 크롬에 자동 반영"까지를 담당합니다. **파일을 각 PC로 내려받는 단계**는 v1.13.2부터 위의 "🚀 자동 배포"가 담당합니다 (git 설치 불필요). 그 외 대안:

| 방법 | 자동화 수준 | 필요 조건 |
|---|---|---|
| 🚀 자동 배포 (v1.13.2+, 기본) | 완전 자동 | PC마다 `INSTALL.bat` 1회 + 저장소 Public 또는 읽기 토큰 |
| Chrome 웹스토어 비공개 게시 | 완전 자동 (크롬이 몇 시간마다 갱신) | 개발자 등록비 $5(1회) + 업데이트마다 심사 대기 |
| ZIP 전달 후 폴더 덮어쓰기 | 수동 배포 + 자동 반영 | 없음 (덮어쓰면 각 PC에서 자동 리로드됨) |

### "Google 로그인 실패: bad client id"
→ OAuth 클라이언트의 애플리케이션 ID가 `clgekekmmlpiggplilhgagfkepepjelk` 와 일치하는지 확인

→ 바디코디 스케줄 페이지가 완전히 로딩된 후 다시 시도 (페이지 진입 직후에는 dhtmlxScheduler가 아직 준비 안 됨)

### Chrome 재시작 시 확장이 사라짐
→ **v1.8.2의 `INSTALL.bat`**을 실행하면 Chrome 바로가기에 `--load-extension` 플래그가 자동 주입되어, Chrome을 어떻게 켜든 확장이 매번 강제로 로드됩니다. 이게 가장 확실한 해결책입니다.
→ 만약 INSTALL.bat 실행 후에도 사라지면:
   1. 작업표시줄에 핀된 Chrome 아이콘을 우클릭 → 제거
   2. 데스크탑이나 시작메뉴의 Chrome 아이콘 우클릭 → 속성 → "대상" 끝에 ` --load-extension="C:\Users\<사용자명>\AppData\Local\bodycodi-sync"` 가 들어있는지 확인
   3. 그 아이콘을 다시 작업표시줄에 핀
   4. Chrome을 완전히 종료한 후, 핀된 아이콘으로 다시 시작

### 동기화 결과에 다음 주 이후 일정이 안 나옴

### 캘린더 설명에 손으로 적은 메모가 사라짐

### 설명에 "유효기간" 줄이 안 나옴
→ 확장은 바디코디 예약 데이터의 만료일 필드를 후보 이름(`useEndDate`, `expireDate` 등)과 "end/expire/limit/valid"가 들어간 날짜형 필드(중첩 객체 1단계, epoch 숫자 포함)로 찾습니다. 예약 당일과 같은 날짜는 예약 시각으로 보고 제외합니다.
→ 팝업 로그의 `📆 유효기간 추출:` 줄을 확인하세요.
   - `만료일=N/M (필드=xxx)` → 정상. `필드=` 값이 엉뚱한 필드(예: 등록일)라면 관리자에게 알려 주세요.
   - `0/M — 날짜형 필드 후보: {...}` → 예약 데이터에 만료일이 없거나 이름이 다른 경우입니다. 이때는 바로 아래 `📡` 줄도 함께 확인합니다.
→ `📡` 줄 (v1.13.1 이용권 응답 탐지기): 바디코디 페이지가 서버에서 받은 응답 중 잔여/만료/유효 키가 있는 것의 **요청 주소와 키 이름·날짜 값만** 기록합니다 (회원 이름·연락처는 기록하지 않음).
   - `📡 탐지기 미작동` → 바디코디 탭이 확장 설치 전에 열린 상태입니다. 탭을 새로고침하세요.
   - `📡 서버 응답 없음` → 바디코디에서 **회원 상세(이용권) 화면을 한 번 연 뒤** 다시 동기화하면 기록됩니다.
   - `📡 POST /manager/... → {"...validEndDate":"2026-12-31", ...}` → 이 줄들을 관리자에게 그대로 전달해 주세요. 유효기간을 내려주는 요청을 확인해 다음 버전에서 연결합니다.
