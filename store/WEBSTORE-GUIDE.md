# 크롬 웹스토어 등록 안내서 (처음 하는 분용)

> ✅ **이미 등록된 항목이 있습니다** (항목 ID `heojbjjphafhlepaopagaejebacclfmc`, 상태 "게시됨 - 미등록").
> 그래서 아래 1~4단계(개발자 등록, 첫 ZIP 만들기, 새 항목 업로드, ID 확인)는 **건너뜁니다.**
> 대신 이 항목 ID로 구글 로그인 설정(OAuth 클라이언트)을 하나 만들고, 그 클라이언트 ID를 관리자에게 보내면 그 값을 넣은 스토어용 ZIP을 받게 됩니다.
> 그다음 "패키지 → 새 패키지 업로드"로 올리고 5단계부터 진행하세요.

웹스토어에 올리면 크롬이 새 버전을 **스스로** 내려받습니다. 직원 PC에서 버튼을 누르거나 스크립트를 돌릴 일이 없어집니다.

| 누가 | 무엇을 | 걸리는 시간 |
|---|---|---|
| 원장님 (1회) | 1~8단계: 개발자 등록, 업로드, 문구 붙여넣기, 제출 | 약 40분 |
| 구글 | 검토 | 보통 1~3일, 길면 1주 |
| 원장님 (PC마다 1회) | 9단계: 옛 확장 지우고 스토어에서 설치 | PC당 5분 |
| 이후 버전업 | 제가 드리는 ZIP을 대시보드에 올리기 | 2분 |

**준비물**
- 크롬, 그리고 지금 확장의 구글 로그인 설정(OAuth)을 만든 **관리자 구글 계정**
- 해외 결제 가능한 카드 (등록비 5달러, 1회)
- 제가 보내 드린 `bodycodi-sync-v1.16.0.zip`
- 처음 설치할 때 받은 개인키 파일 `bodycodi-sync_PRIVATE_KEY_관리자보관용.pem`
  - 보통 처음 압축을 풀었던 폴더의 바로 위 폴더에 있습니다.
  - 못 찾아도 진행할 수 있습니다 (맨 아래 B안).

## 1단계. 개발자 계정 등록 (10분, 처음 한 번만)

1. 크롬에서 아래 주소를 엽니다.
   ```
   https://chrome.google.com/webstore/devconsole
   ```
2. 관리자 구글 계정으로 로그인합니다.
3. 개발자 계약에 동의하고 **등록비 5달러**를 결제합니다.
4. **게시자 이름**을 적습니다. 예: 센터 이름.
5. **연락처 이메일**을 적고, 그 메일함에 온 확인 메일의 링크를 누릅니다.
6. "판매자(Trader)인가요?" 질문이 나오면 **비판매자(Non-trader)** 를 고릅니다. 판매하지 않는 내부 업무 도구이기 때문입니다.

> 구글 계정에 2단계 인증이 꺼져 있으면 켜라는 안내가 나올 수 있습니다. 안내대로 켜면 됩니다.

## 2단계. 첫 업로드용 ZIP 만들기 (2분)

1. `bodycodi-sync-v1.16.0.zip`을 **우클릭 → 압축 풀기**로 풉니다.
2. 풀린 `bodycodi-sync` 폴더 → `store` 폴더로 들어갑니다.
3. **`MAKE-STORE-ZIP.bat`** 을 더블클릭합니다.
   - "Windows의 PC 보호" 파란 창이 뜨면 **추가 정보 → 실행**을 누릅니다.
   - 개인키를 자동으로 못 찾으면 파일 선택 창이 뜹니다. `.pem` 파일을 골라 주세요.
4. 창에 "바탕화면에 만들어졌습니다"가 나오면 Enter를 눌러 닫습니다.
5. 바탕화면에 아래 파일이 생겼는지 확인합니다.
   ```
   bodycodi-sync-store-FIRST-v1.16.0.zip
   ```

> ⚠️ 이 ZIP에는 개인키가 들어 있습니다. 웹스토어 대시보드에 올리는 것 말고는 메일, 카톡, 드라이브 어디에도 보내지 마세요. 업로드가 끝나면 지웁니다.

## 3단계. 업로드 (2분)

1. 개발자 대시보드에서 **+ 새 항목** 버튼을 누릅니다.
2. 바탕화면의 `bodycodi-sync-store-FIRST-v1.16.0.zip`을 고르고 업로드합니다.
3. 업로드가 끝나면 항목 편집 화면으로 바뀝니다.

## 4단계. ★ 확장 ID 확인 (30초, 제일 중요)

업로드 직후 화면 위쪽, 또는 주소창 끝에 32자리 영문 ID가 보입니다.

```
https://chrome.google.com/webstore/devconsole/.../여기가_ID/edit
```

그 ID를 아래 값과 비교합니다.

```
clgekekmmlpiggplilhgagfkepepjelk
```

- **같으면 (A안)**: 구글 로그인 설정을 바꿀 필요가 없습니다. 5단계로 갑니다.
- **다르면 (B안)**: 아직 제출하지 말고, 맨 아래 **B안**을 먼저 하세요.

ID 확인이 끝나면 바탕화면의 `...-FIRST-...zip`은 지웁니다.

## 5단계. "스토어 등록정보" 탭 (10분)

`store/STORE-LISTING.md` 파일의 **A** 부분을 칸마다 복사해 붙여 넣습니다.

- 설명: A의 회색 상자 내용
- 카테고리: 생산성 → 업무 흐름 및 계획
- 언어: 한국어
- 이미지: `icons/icon128.png`, `store/screenshot-1280x800.jpg`, `store/promo-440x280.jpg`

**임시저장**을 누릅니다.

## 6단계. "개인정보 보호" 탭 (10분)

`store/STORE-LISTING.md` 파일의 **B** 부분을 순서대로 붙여 넣고 체크합니다.

- 단일 목적
- 권한마다 사용 이유 (storage, identity, alarms, scripting, tabs, 호스트 권한)
- 원격 코드: **아니요**
- 데이터 사용: **개인 식별 정보**, **웹사이트 콘텐츠** 두 개만 체크
- 아래 세 문장 모두 체크
- 개인정보처리방침 URL 붙여넣기

**임시저장**을 누릅니다.

## 7단계. "배포" 탭 (1분)

- 결제: **무료**
- 공개 범위: **미등록 (Unlisted)**
- 지역: 모든 지역

**임시저장**을 누릅니다.

## 8단계. 제출

1. 오른쪽 위 **검토를 위해 제출**을 누릅니다.
2. "승인 후 자동 게시" 옵션은 **켠 채로** 둡니다.
3. 결과는 등록한 연락처 이메일로 옵니다. 반려 메일이 오면 그 내용을 저에게 그대로 보내 주세요. 고쳐서 다시 드리겠습니다.

## 9단계. 승인 후, 직원 PC 전환 (PC마다 5분)

먼저 대시보드의 **스토어 등록정보 → 상세 페이지 보기** 링크를 복사해 둡니다. 이 링크로 설치합니다.

각 PC에서 순서대로 합니다.

1. 예전에 받은 폴더의 **`UNINSTALL.bat`** 을 더블클릭하고 Enter를 누릅니다.
   - 옛 자동 업데이트 작업과 옛 확장 폴더가 지워집니다.
2. 크롬 주소창에 `chrome://extensions`를 입력합니다.
3. "BodyCodi → Google Calendar Sync" 카드가 남아 있으면 **삭제**를 누릅니다.
4. 크롬을 완전히 껐다가 다시 켭니다.
5. 복사해 둔 스토어 링크를 열고 **Chrome에 추가**를 누릅니다.
6. 바디코디 스케줄 화면을 열고 확장 아이콘을 누릅니다.
7. **강사 목록 불러오기 → 구글 로그인 → 강사별 캘린더 확인 → 매핑 저장**을 합니다.
   - 설치를 새로 했기 때문에 매핑을 한 번 다시 저장해야 합니다.
8. 버튼 사이 드롭다운에서 자동 동기화 주기를 고릅니다.

이후로는 크롬이 알아서 업데이트합니다.

## 10단계. 앞으로 버전이 올라갈 때 (2분)

1. 제가 `bodycodi-sync-store-v{버전}.zip`을 보내 드립니다. 개인키는 들어 있지 않습니다.
2. 대시보드 → 항목 → **패키지** 탭 → **새 패키지 업로드** → ZIP 선택.
3. **검토를 위해 제출**을 누릅니다.
4. 승인되면 각 PC의 크롬이 보통 몇 시간 안에 새 버전으로 바꿉니다.

## B안. 확장 ID가 달라졌거나 개인키를 못 찾은 경우 (15분)

ID가 바뀌면 구글 로그인 설정에 새 ID를 알려 줘야 합니다.

1. 아래 주소를 관리자 구글 계정으로 엽니다.
   ```
   https://console.cloud.google.com/apis/credentials
   ```
2. 위쪽 프로젝트 이름이 지금 확장에 쓰는 프로젝트인지 확인합니다.
3. **+ 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**를 누릅니다.
4. 애플리케이션 유형: **Chrome 확장 프로그램**
5. 이름: `bodycodi-sync store`
6. 항목 ID: 4단계에서 본 **새 ID**를 붙여 넣습니다.
7. **만들기**를 누르고, 나온 **클라이언트 ID**를 복사합니다.
   ```
   예) 123456789012-abcdefg....apps.googleusercontent.com
   ```
8. 그 클라이언트 ID와 새 확장 ID를 저에게 보내 주세요.
9. 제가 새 클라이언트 ID를 넣은 스토어용 ZIP을 만들어 드립니다.
10. 대시보드 → **패키지** 탭 → **새 패키지 업로드**로 그 ZIP을 올린 뒤 5단계부터 계속합니다.

> OAuth 동의 화면이 "테스트" 상태라면, 직원 구글 이메일이 **테스트 사용자**에 들어 있어야 로그인됩니다. 지금 쓰는 명단이 그대로 적용됩니다.

## 자주 묻는 것

**Q. 승인 전까지 지금 쓰던 건 어떻게 되나요?**
지금처럼 그대로 동작합니다. 9단계 전까지는 아무것도 바뀌지 않습니다.

**Q. 아무나 설치할 수 있나요?**
"미등록"은 링크를 아는 사람만 설치할 수 있고 검색에는 나오지 않습니다. 설치해도 바디코디 로그인과 강사 매핑 없이는 아무 동작도 하지 않습니다.

**Q. 개인키를 대시보드에 올려도 괜찮나요?**
첫 업로드 때 기존 ID를 이어받기 위해 크롬이 안내했던 방법입니다. 다만 현재 공식 문서에는 이 방법이 명시돼 있지 않아서, 4단계에서 ID를 꼭 확인하도록 했습니다.
